# Job Skill Radar

저장한 목표 직무로 **고용24 공고를 자동 발견하고, 검토할 이유와 원문 근거를 보여주는 개인용 도구**를 목표로 구현했습니다.
보유 기술만으로 검색 범위를 좁히지 않으며 적합도 점수·합격 확률을 만들지 않습니다.

## 프로젝트 상태 — 개발 중단 / 보류

**2026-09-17부터 적극적인 개발을 중단하고 구현·검증 기록을 보존합니다. 후속 Phase는 현재 계획하지 않습니다.**
최종 구현 범위는 Phase 7D 자동 공고 발견 MVP이며, 마지막 코드 변경은 `d7b480e`입니다.

### 보류 사유 — 외부 API 접근과 제품 실현 가능성

원래 제품 흐름은 **저장 프로필 → 공고 자동 발견 → 상세 수집 → 필수·우대 근거 추출 →
프로필 비교 → 설명 가능한 검토 목록**입니다. 이 흐름의 기술적 구현과 자동 검증을 완료한 뒤,
실사용 검증 과정에서 필요한 외부 API의 접근 제약을 확인했습니다.

실사용 시 확인한 Work24 개인회원 API 신청 페이지 안내에 따르면 개인회원은 **채용행사·공채속보·
공채기업정보** 등을 이용할 수 있지만, **채용정보목록·채용정보상세**는 이용할 수 없습니다.
현재 자동 발견 구현은 이 일반 채용 목록·상세 API를 전제로 설계되어 있어,
**일반 개인 Work24 계정을 사용하는 대상 사용자는 핵심 자동 발견 흐름을 이용할 수 없습니다.**
이는 구현 오류가 아니라 실사용 검증에서 드러난 외부 API 접근 및 제품 실현 가능성의 제약이며,
개발 보류의 주된 이유입니다. 개인회원이 이용 가능한 다른 API로 대체하는 기능은 구현하지 않았습니다.

저장·수집·추출·비교·UI/CLI를 연결하고 회귀 검증까지 진행했지만, 원래 제품 목표와 실제 이용 가능
범위가 일치하지 않았습니다. 이 의존성을 전제로 추가 개발하는 비용 대비 가치가 낮다고 판단하여
개발을 보류했습니다. 구현 → 자동 테스트 → 실사용 검증 → 외부 제약 확인 → 보류 순서의 기록을 남깁니다.

### 최종 구현 및 검증 범위

- source를 구분하는 SQLite 영속 저장과 schema v4까지의 마이그레이션.
- Work24 목록·상세 클라이언트, 상세 원문 근거 및 출처·위치 등 provenance 보존.
- 기술 taxonomy·canonicalization, 직무 분류, 근거를 설명하는 학습 추천.
- 필수(`required`)·우대(`preferred`)·업무(`responsibility`)·미분류(`unspecified`) 추출과
  `all_of` / `any_of` 요건 그룹, 요건 평가 fixture corpus.
- 수동 공고 등록, 영속 로컬 사용자 프로필, 설명 가능한 프로필–공고 비교.
- 자동 발견 아키텍처, 발견 실행 영속 저장, 신규/기존 공고 추적, 설명 가능한 발견 검토 목록.
- Streamlit UI, CLI 발견 흐름, Windows/Linux 환경을 고려한 회귀 검증 및 SQLite 자원 정리.

최종 검증 시점에 **자동 테스트 456개가 통과**했습니다. 이는 구현 계약의 회귀 검증이며 운영 환경의
정확도나 개인회원의 실 API 이용 가능성을 증명하지 않습니다. 요건 평가 corpus는 **합성·수작업 fixture**이며
대표성 있는 실제 채용공고 정확도 평가가 아닙니다. 상세 수치는 [검증 기록](docs/TEST_BASELINE.md)에 있습니다.
이번 보류 문서화에서는 코드 변경 없이 문서 diff만 검증하며 전체 테스트를 다시 실행하지 않습니다.

### 실사용에서 확인한 보조 품질 한계

실제 한국어 채용 문장은 합성 평가 corpus보다 복잡했습니다. 다음과 같은 표현에서 보수적 추출이
유용한 근거를 `unspecified`로 남기는 재현율(recall) 한계가 관찰되었습니다.

- Java 또는 Kotlin을 이용한 Spring Framework 애플리케이션 개발 경험 필수
- JPA 또는 Hibernate 등 ORM 사용 및 도메인 모델링 경험 필수
- Docker 또는 Kubernetes 기반 배포·운영 경험 우대

합성 fixture 평가는 통과했지만 실제 공고 표현의 포괄 범위는 충분히 측정되지 않았습니다.
이 관찰만으로 추출기 전체가 부정확하다고 결론짓지는 않습니다. 더 넓은 사용을 신뢰하려면 대표성 있는
실공고 평가 corpus가 필요합니다. 이는 **보조적인 품질 한계**이며 개발 중단의 주된 이유는 API 접근 제약입니다.

### 현재 사용할 수 있는 흐름

**공고 텍스트 수동 등록 → 요건 추출 → 저장한 로컬 프로필 → 설명 가능한 비교**는 API 없이 사용할 수 있습니다.
원문과 근거를 직접 검토하는 도구로는 여전히 활용할 수 있습니다. 다만 원래 목표가 자동 공고 발견이었으므로,
수동 중심 흐름만으로는 추가적인 적극 개발을 이어갈 가치가 충분하지 않다고 판단했습니다.

### 재개 조건

다음 중 적어도 하나가 해결되어야 재개를 검토합니다. 자동 발견 목표를 유지하려면 이용 가능한 데이터 소스가
필요하며, 평가 corpus 준비만으로 API 접근 제약이 해소되지는 않습니다.

1. 개인이 접근 가능한 공식 채용 API에서 충분한 공고 목록·상세 데이터를 확보할 수 있음.
2. 자동화 이용 조건이 수용 가능하고 법적·운영상 적절한 다른 소스를 확인함.
3. 제품 목표를 자동 발견에서 수동 공고 분석 도구로 의도적으로 변경함.
4. 요건 추출기를 검증할 대표성 있는 실공고 평가 corpus를 준비함.

재개 조건은 현재 실행 계획이 아닙니다. 스크래핑을 기본 대안으로 정하지 않으며 후속 개발은 진행하지 않습니다.

## 시작하기

```bash
cd ~/Dev/job-skill-radar
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

이미 가상환경이 있으면 마지막 명령만 실행하세요. Windows에서는 `.venv\Scripts\python.exe`를
사용하거나 `scripts/start_dashboard.ps1`로 실행할 수 있습니다.
[다른 PC 설정](docs/04_other_pc_setup.md)도 참고하세요.

현재 개인회원은 실행 후 **내 프로필 저장 → 공고 직접 등록 → 공고 목록 → 원문/요건/프로필 비교**를
사용할 수 있습니다. 아래 자동 발견 절차는 **채용정보목록·채용정보상세 API 이용 권한이 있는 환경**을
전제로 남긴 구현 사용법이며, 일반 개인회원은 키 발급만으로 이 흐름을 사용할 수 없습니다.

1. **내 프로필**에서 보유 기술과 목표 직무를 저장합니다. 지역 선호와 필수 조건은 다릅니다.
2. 고용24에서 발급받은 키를 프로젝트 `.env`의 `WORK24_AUTH_KEY`에 설정하고 앱을 재시작합니다.
   `.env.example` 형식을 참고하고 실제 키를 Git·공유 화면·메시지에 넣지 마세요.
3. **새 공고 찾기**에서 자동 검색어를 확인하고 같은 이름의 버튼을 누릅니다. 키워드 입력은 필요 없습니다.
4. 새로 발견한 공고와 검토 분류를 확인하고 **공고 열기**로 원문·요건·AND/OR 조건을 봅니다.
5. **내 프로필과 비교**를 선택해 필수·우대·업무 기술과 프로필 등록 여부, 정확한 근거를 확인합니다.

다음 날에는 앱을 열고 저장된 최근 실행을 먼저 확인한 뒤 버튼으로 한 번 검색하세요.
필터 변경·앱 재실행만으로는 외부 요청을 보내지 않습니다. 최근 20회 실행을 선택해 볼 수 있습니다.
‘새 공고’는 **해당 검색에서 이 로컬 DB에 처음 발견한 공고**이지 오늘 고용주가 게시했다는 뜻은 아닙니다.
과거 실행을 열어도 검토 분류는 현재 프로필과 현재 저장 원문으로 다시 계산합니다.

API 키가 없어도 **공고 직접 등록 → 공고 목록 → 원문/요건/프로필 비교**는 사용할 수 있습니다.
Wanted·Jumpit·사람인·LinkedIn·회사 채용 페이지 등은 사용자가 직접 복사해 등록하는 방식이며
자동 접속·스크래핑하지 않습니다. 자동 검색 source는 Work24뿐입니다.

## 검토 분류의 의미

| 분류 | 의미 |
|---|---|
| 먼저 검토 | 목표 직무이며 현재 분류 가능한 근거에서 필수 프로필 미등록이 검출되지 않음. 자격 충족 판정은 아님 |
| 필수 요건 확인 필요 | 독립 필수 기술 또는 필수 AND/OR 조건을 현재 프로필 등록만으로 확인하지 못함 |
| 정보 부족 | 상세/자격 근거 부족, 역할 미분류, 미해석·충돌 근거, 판단할 수 없는 필수 지역 조건 |
| 현재 목표/조건 밖 | 명시적으로 다른 직무이거나 정확한 근거로 확인된 필수 조건 불일치. 공고를 숨기지는 않음 |

우대 미등록은 필수 부족이 아닙니다. OR는 하나의 선택 조건이며, 하나를 등록하면 그 그룹은 충족됩니다.
‘프로필에 미등록’은 실제로 그 기술을 모른다는 뜻이 아닙니다. 원문과 마감 여부를 직접 확인하세요.
지역 비교는 원문 전체가 정확한 단일 시·도 label일 때만 판단합니다. 상세 주소·복수 지역 등은 unknown입니다.

## 요청 예산과 갱신

- 기존 8개 직무마다 고정 검색어 2개, 전체 최대 16개입니다. 보유 기술은 검색 필터가 아닙니다.
- 기본 질의당 1페이지·20건, 상세 요청 최대20회입니다. 백엔드만 선택하면 최대 목록2회+상세20회입니다.
- 상세는 새 공고, 상세 없는 기존 공고 순으로 가져오고 기존 성공 상세는 재사용합니다.
- **상세 갱신 옵션**에서 명시적으로 요청한 경우만 기존 성공 상세를 다시 가져옵니다. 같은 예산을 적용합니다.
- 실패한 상세는 기존 성공 원문을 지우지 않습니다. 예산 미수집과 요청 실패는 따로 표시합니다.
- 일부 질의/상세 실패는 부분 완료로 저장합니다. 모든 질의 실패도 실행 기록을 남깁니다.
- 검색어 recall, 실공고 추출 정확도, 공고의 현재 유효성은 보장하지 않습니다. 재시도·상시 감시는 없습니다.

## 일회성 CLI / 예약 실행 준비

채용정보목록·채용정보상세 API 이용 권한이 있는 환경에서 프로필을 먼저 앱에 저장하고 키를 설정한 뒤 실행합니다.
일반 개인회원의 API 접근 제약은 CLI에서도 동일합니다.

```bash
.venv/bin/python -B scripts/discover_jobs.py
.venv/bin/python -B scripts/discover_jobs.py --json
.venv/bin/python -B scripts/discover_jobs.py --pages 2 --display 20 --max-details 30
.venv/bin/python -B scripts/discover_jobs.py --refresh-existing-details --max-details 10
```

허용 범위: pages 1~2, display 1~50, max-details 0~50. 최대로 설정해도 목록32회+상세50회 이내입니다.
앱 자체 제한이며 공식 API rate limit을 주장하지 않습니다. `--db-path /absolute/path/radar.sqlite`도 지원합니다.
종료 코드는 **0=완료, 2=부분 완료 및 성공 자료 저장, 1=설정/실행 불가 또는 모든 질의 실패**입니다.
JSON 성공/부분/실패 결과에는 실행 정보만 있으며 원문 본문·키·인증 URL은 출력하지 않습니다.

cron/systemd timer/작업 스케줄러에 연결 가능한 일회성 명령입니다. 이 프로젝트는 스케줄러를 설치하지
않고 데몬을 실행하지 않습니다. 예약 시 Python·스크립트·DB 경로를 고정하고 중복 실행은 피하세요.
기존 수동 키워드 CLI `scripts/collect_work24.py`와 샘플 `scripts/run_demo.py`도 유지됩니다.

## 저장·이전·검증

SQLite 기본 경로는 `data/job_skill_radar.sqlite`, 변경은 `JOB_RADAR_DB_PATH`입니다.
현재 schema v4이며 첫 실행에서 v0/v1/v2/v3를 이전합니다. 먼저 기존 앱/다른 writer를 종료하세요.
기존 파일은 `<DB>.pre-v4-from-vN-고유값.bak`으로 백업하고 이전 실패 시 rollback합니다.
공고·원문·프로필·시각을 보존하며 current DB 재개방은 백업을 반복하지 않습니다.
다운그레이드 시 현재 DB를 구버전 앱으로 열지 말고 종료 상태에서 이전 백업 복사본을 복구하세요.

```bash
python -B -m unittest discover -s tests
python -B scripts/evaluate_requirements.py
python -B scripts/run_demo.py
```

자동 검증은 API 키/실제 Work24 네트워크 없이 임시 DB와 가짜 응답으로 수행합니다.
합성 fixture 평가는 실공고 정확도가 아닙니다. Phase 7D 완료 당시 실제 API smoke는 키와 프로필이 없어 생략했습니다.
이후 실사용 검증에서 확인한 API 접근 제약과 추출 한계는 위 프로젝트 상태에 기록했습니다.
시장 분석은 수동 공고를 제외한 수집 Work24 표본만 사용하며 전체 시장을 대표한다고 볼 수 없습니다.
숫자 매칭·지원 추적·추세 분석·다른 사이트 자동 수집은 구현하지 않았습니다.
